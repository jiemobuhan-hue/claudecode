# 会话总结_20260501_自动机并行化改造v2

**日期**: 2026-05-01（下午）
**会话目标**: 修复自动机并行化的遗留问题（重复执行、Task.WaitAll阻塞、无超时保护）

## 一、新发现的问题（本次修复）

| # | 问题 | 严重度 | 原因 |
|---|------|--------|------|
| N1 | `Task.WaitAll()` 全阻塞，任一通道慢则全部卡住 | P0 | 同步等待所有Task完成 |
| N2 | `GetInt_Plc` 无超时保护，PLC无响应时永远阻塞 | P0 | 无 CancellationTokenSource 超时 |
| N3 | 触发信号电平型无边缘检测，持续=1会重复执行 | P0 | ProcessChannel 入口未判断边沿 |
| N4 | `\|\|true` 硬编码导致 ProductLeadArrive 无条件执行 | P1 | 原代码遗留 |
| N5 | 无通道状态锁存，无法防止处理中重复进入 | P2 | 缺少 Processing 状态追踪 |

**用户确认**:
- 超时处理：超时通道跳过，其他通道继续
- 轮询方式：保持当前轮询+超时保护

## 二、问题详解

### N1: Task.WaitAll() 全阻塞

```csharp
// 改造前：任一通道慢，全部被卡住
Task.WaitAll(triggerTasks);   // 等待全部4个读完成
Task.WaitAll(arriveTasks);    // 等待全部4个处理完成
```

**修复**：改用 `Task.WhenAll` + `async/await`，让等待不阻塞主循环

### N2: GetInt_Plc 无超时

```csharp
// 改造前：PLC 无响应时永远阻塞
private int GetInt_Plc(string name)
{
    lock (_plcLock) {
        var resint = int.Parse(PlcHandler.I._omronFins.omronFinsNet.ReadUInt16(obj.Adress).Content.ToString());
    }
}
```

**修复**：添加 `CancellationTokenSource(timeoutMs)` 超时机制，超时返回 -1

### N3: 触发信号重复执行

```
Cycle N:   触发=1 → ProcessChannel → 完成但未清除触发
Cycle N+1: 触发=1 → ProcessChannel 又执行一次 ← 同一电芯重复入站
```

**修复**：边缘检测 `if (trigger == state.TriggerLast) return;`

### N4: ||true 无条件执行

```csharp
// 改造前：无条件执行
if (GetInt_Plc($"PLC通道{no}分流触发")==1||true)
```

**修复**：移除 `||true`，严格按触发信号判断

### N5: 无状态锁存

**修复**：添加 `ChannelState` 类追踪 `Processing` 状态

## 三、已执行修改

### 1. 添加 ChannelState 类和数组

```csharp
private class ChannelState {
    public int TriggerLast { get; set; } = 0;
    public bool Processing { get; set; } = false;
    public string LastCode { get; set; } = "";
    public long LastProcessTime { get; set; } = 0;
}
private ChannelState[] _channelStates = new ChannelState[5];
```

### 2. GetInt_Plc 加超时保护

```csharp
private int GetInt_Plc(string name, int timeoutMs = 3000)
{
    var cts = new CancellationTokenSource(timeoutMs);
    try {
        lock (_plcLock) {
            result = int.Parse(PlcHandler.I._omronFins.omronFinsNet.ReadUInt16(obj.Adress).Content.ToString());
        }
    }
    catch (OperationCanceledException) {
        Rlog.Error($"PLC读取超时 [{name}]");
        return -1; // 超时返回 -1
    }
    finally { cts.Dispose(); }
}
```

### 3. ProcessChannel_ProductArrive 加边缘检测+状态锁

```csharp
var trigger = GetInt_Plc($"PLC通道{no}来料触发");
if (trigger <= 0) { state.Processing = false; return; } // 无触发或超时
if (trigger == state.TriggerLast) { return; } // 电平未变，跳过
state.TriggerLast = trigger;

if (state.Processing) { return; } // 上次处理未完成，跳过
state.Processing = true;
// ... 处理逻辑 ...
finally { state.Processing = false; }
```

### 4. ProcessChannel_ProductLeadArrive 同理改造

同样加边缘检测 + 状态锁存

### 5. 重写 Thread_Run 非阻塞并行

```csharp
private async Task Thread_Run()
{
    while (_running) {
        // 并行启动8个工位任务（触发判断由各ProcessChannel自己完成）
        var allTasks = Enumerable.Range(1, 4)
            .SelectMany(i => new[] {
                Task.Run(() => ProcessChannel_ProductArrive(i)),
                Task.Run(() => ProcessChannel_ProductLeadArrive(i))
            })
            .ToArray();

        try {
            await Task.WhenAll(allTasks);
        }
        catch (OperationCanceledException) { }
        catch (AggregateException) { }

        Thread.Sleep(Settings.自动机循环等待);
    }
}
```

**变化**：去除了预读触发信号的阶段（triggerTasks/leadTriggerTasks），改为由各 ProcessChannel 自己判断边沿

## 四、关键行为对比

| 场景 | 改造前 | 改造后 |
|------|--------|--------|
| 通道1 PLC慢（5秒） | 通道2/3/4全被卡住 | 通道1超时返回-1跳过，2/3/4继续 |
| 触发信号持续=1 | 重复执行同一电芯入站 | 边缘检测，触发从0变1才执行 |
| 分流触发=0 | 因 \|\|true 仍执行 | 严格判断，触发=0则跳过 |
| PLC断开 | Task继续运行 | GetInt_Plc 超时返回-1，通道跳过 |
| 某通道处理中再来触发 | 无法识别，重复执行 | Processing状态锁存，跳过 |
