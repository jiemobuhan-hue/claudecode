01

命令详解

1
flowchart
PHASE 1 · 需求分析
输入工位的自然语言描述，输出标准的 Mermaid 时序图和状态迁移图。 自动识别异常分支（超时/重试/降级），标注 PLC 地址别名。
$ /plc-dev flowchart "通道1来料：PLC触发→PC扫码→MOM查单→回写结果。超时3秒重试，MOM不可用走离线队列"
→ 生成 sequenceDiagram + stateDiagram + 信号清单
2
define-signals
PHASE 2 · 信号定义
从确认的流程图中自动提取所有 PLC↔PC 交互点， 按命名规范生成信号名，建议空闲地址，追加到 signals_config.csv。
$ /plc-dev define-signals
→ 从流程图提取 4 个信号 · 分配地址 D3000-D3003 · 写入 CSV
3
gen-station
PHASE 3 · 代码生成
基于流程图 + 信号表，生成完整的 IStationHandler 实现类。 包含心跳检查、信号等待、动作执行三步循环，以及超时/重试/异常处理。
$ /plc-dev gen-station --type Arrive --channel 1
→ 生成 NewStationHandler.cs · ~120 行 · 注册到 AutoRun.Init()
4
validate
PHASE 4 · 一致性校验
6 项全量检查：CSV→代码引用、代码→CSV 存在性、地址冲突、 读写方向一致性、心跳信号存在、触发-结果成对。输出分级报告。
$ /plc-dev validate
→ ✅ 48 通过 · ⚠️ 2 警告 · ❌ 0 错误 · 报告已生成
5
diag
PHASE 5 · 故障诊断
五层逐级排查：物理连接 → PLC 连接状态 → 心跳信号 → 单信号读写测试 → 工位状态机逻辑。每层输出诊断结论和修复建议。
$ /plc-dev diag "通道3来料不触发"
→ L3 心跳正常 · L4 信号 D1004=0 → PLC 侧未置位，检查传感器
✦
scaffold
新项目脚手架
一键生成 PLC 通信层完整项目骨架：PlcMonitor + PlcChannel + ConnectionFactory + SignalReader + RetryPolicy + 配置模板 + IStationHandler 接口。
$ /plc-dev scaffold --brand Omron --plcs 2
→ 生成 12 个文件 · 含 plc_config.json + signals_config.csv + ELECTRICAL.md
02

完整工作流示例

场景：为新产线添加通道 5 来料工位

从零开始，5 步完成 PLC 对接开发

  1. 描述需求 — /plc-dev flowchart "通道5来料：PLC触发→PC扫码→MOM查单→回写结果。异常：扫码超时3秒重试2次，MOM不可用走离线队列"
    输出：Mermaid 时序图（含 alt 超时分支）+ 状态迁移图 + 5 个信号候选
  2. 定义信号 — /plc-dev define-signals
    自动提取信号：PLC通道5来料触发(D3000) / 来料电芯码(D3001) / 来料结果(D3002) / 来料复投触发(D3003) / 来料复投信息(D3004)
    用户确认后写入 signals_config.csv
  3. 生成代码 — /plc-dev gen-station --type Arrive --channel 5
    生成 ProductArriveStationHandler5 类，包含完整的 CheckHeartbeatAsync / WaitForSignalAsync / ExecuteActionAsync
    自动注入：超时重试（3 次 × 3s）、MOM 离线队列降级、CancellationToken 检查
  4. 校验一致性 — /plc-dev validate
    检查新增的 5 个信号是否都有代码引用，地址 D3000-D3004 是否与现有信号冲突，读写方向是否正确
  5. 部署后诊断（如需要）— /plc-dev diag "通道5来料不触发"
    逐层排查：ping PLC → 连接状态 → 心跳 → D3000 值 → 工位日志

架构模式

PlcMonitor — 顶层管理器
加载 JSON/CSV 配置 · 创建 PlcChannel 列表 · 暴露 TryGetLatestByName / ReadOnceByNameAsync / WriteByNameAsync · 全局心跳管理
│
│
▼
PlcChannel — 单 PLC 通道
连接-轮询-重连循环 · ConcurrentDictionary 信号值缓存 · Rx Subject<SignalUpdate> 推送 · RetryPolicy 指数退避 (500ms→30s)
│
│
▼
IPlcConnection — 品牌无关接口
OmronConnection / SiemensConnection / ModbusConnection / MitsubishiConnection · Connect() · Read<T>() · Write() · PlcConnectionFactory 自动路由

设计原则

  • 配置驱动 — PLC IP/端口/信号全部通过 JSON/CSV 管理，不硬编码
  • 按名称访问 — 业务代码用信号名（如 "PLC通道1来料触发"），不写地址字符串
  • 信号值缓存 — 最新值常驻内存，业务代码读缓存不触发 I/O
  • 推送模式 — 信号更新通过 Rx Subject 推送订阅者（UI 监控面板等）
  • 指数退避重连 — base 500ms, max 30s, 最多 10 次重试

工位状态机模式

// IStationHandler 接口契约
public interface IStationHandler
{
    // 检查通道心跳，失败抛异常
    Task<bool> CheckHeartbeatAsync(token);

    // 等待触发信号，超时返回 false
    Task<bool> WaitForSignalAsync(token);

    // 执行业务逻辑，写结果回 PLC
    Task ExecuteActionAsync(token);
}

常见问题速查

现象最可能原因检查
所有工站停摆全局心跳丢失PLC 连接状态，ping 测试
某通道不触发触发信号未置位PLC 在线监控触发寄存器值

模拟与测试

无硬件开发模式

App.config 中设置 SimulationMode=true， SimulationDataGenerator 周期性生成假数据写入 SQLite，模拟电芯码以 SIM 前缀标识。

本地测试 PLC 配置使用 127.0.0.1 回环地址，配合软 PLC 或模拟器。 PlcChannel 连接失败时不崩溃，进入自动重连循环。

测试策略

测试对象方式
SignalReader 类型分发Mock IPlcConnection，验证各类型 Read<T> 调用
PlcChannel 重连逻辑Mock 连接断开，验证重试次数和间隔
Station 状态流转Mock IStationHandler，验证循环逻辑
配置加载测试 JSON/CSV 解析结果
